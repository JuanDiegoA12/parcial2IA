# Implementation Plan — Python sinusoidal gait for DARwIn-OP

Goal: replace the non-functional locomotion stub with a Python sinusoidal gait that drives the DARwIn-OP leg motors directly via `setPosition`, keep the agents' high-level discrete actions (0 walk_forward, 1 turn_left, 2 turn_right) unchanged, fix fall detection, and keep the headless pytest suite green. Validate a single robot (stand / forward / turn) BEFORE integrating with the four agents.

- **Motors are not inline.** The 20 motors and their `<name>+"S"` PositionSensors are provided by the PROTO; in Webots they are fetched with `Supervisor.getDevice(name)` / `getMotor(name)` (the mock implements both). `supervisor TRUE` is set on each robot, so `getSelf()` works.
- **Stub root cause (confirmed by reading code).** `_LocomotionBackend` tries `from managers import ...`; that module is C++-only and raises `ModuleNotFoundError` in Python, so it always falls to the stub. The stub's walk/turn/stand only call `supervisor.queue_action(...)`, which exists ONLY in the test mock (`FakeSupervisor.queue_action` + `_apply_kinematics`), not in real Webots. So in Webots nothing drives the legs; the robot collapses and joints rest against limits — consistent with `hidden rotation_18 ... 2.2500013...` (knee at 2.25) in the `.wbt`. The stub never commands ±2.25.
- **Mock kinematics dependency (critical compatibility constraint).** Headless tests move the robot purely through `queue_action` + `_apply_kinematics` in `FakeSupervisor.step()`. Tests that rely on this: `test_darwin_robot.py::test_walk_forward_advances_toward_goal`, `::test_turn_changes_heading`; `test_race_env.py::test_forward_progress_is_positive`, `::test_crossing_goal_grants_bonus_and_terminates`, `::test_truncation_at_max_steps`; `test_race.py`; SB3 smoke/custom-agent tests via `run_race`. The new gait MUST keep calling `queue_action` (the existing `_queue` path) so the mock still advances. The real `setPosition` commands only matter inside Webots.
- **Fall detection mismatch.** `is_fallen()` assumes a gravity-style accelerometer `(0,0,g)` and computes `tilt=atan2(hypot(ax,ay), |az|)`. The mock's `force_tilt` encodes the same gravity model. Webots DARwIn-OP accelerometer actually reads centered ~512 per axis when standing (Walk.cpp compares `acc[1]` against `512 ± 80`). Task 4 rewrites this and must update `force_tilt` + the two fall tests (`test_darwin_robot.py::test_is_fallen_threshold`, `test_race_env.py::test_fall_penalizes_and_terminates`) coherently.
- **Pre-existing, unrelated test failure.** `tests/test_wbt.py::test_robot_geometry_and_flags_unchanged` ALREADY fails on the current tree: the user moved the robots inside Webots, so `./pista_atletismo_50m.wbt` has DQN at `(0.21881, 9.95112, 0.22402)` while the test/config expect `(0.11, 9.95, 0.24)`. This is caused by the user's world edits, not by this task, and fixing it would require editing robot geometry, which is forbidden. Treat this single failure as a known baseline; do NOT "fix" it by touching the world. All OTHER 50 tests currently pass (`50 passed, 1 failed`).
